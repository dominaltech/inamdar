## 1. Overview & Objectives

This implementation plan covers the complete set of architectural refinements, workflow enhancements, and UI polish requested for the Inamdar Restaurant POS system. All features maintain the authentic Windows 98 / 2000 Menson's POS keyboard-driven ergonomics, with Supabase as the live backend source of truth.

---

## 2. Feature Breakdown & Implementation Tasks

### 2.1 Unified Table Column Headings & Entry Row (`OrderWorkspace.jsx`)
- **Current Problem:** An isolated gray container with `Code/CTM`, `Dish Name`, `Qty`, `Rate`, `Custom` floats separately above the items grid table, causing visual misalignment with the table column headers (`Code`, `Item Name`, `Qty`, `Rate`, `Amount`, `Status`).
- **Solution:** 
  - Merge the input controls directly into the table's header/entry row.
  - The input fields (`Code`, `Item Name`, `Qty`, `Rate`, `Amount`, `Custom/Status`) align with the exact column widths of the items grid.
  - The autocomplete dropdown anchors directly beneath the Code input within the column.
  - Produces an authentic, unified Menson's POS tabular order entry experience.

### 2.2 Customer Details Modal in New Order (`CustomerDetailsModal.jsx` & `OrderWorkspace.jsx`)
- **Requirement:** When starting a new order on a table (e.g. entering Table `1` and pressing Enter), prompt for Customer Details before entering dishes:
  - **Customer Name** (Text, autofocus, optional, default: empty or 'Guest')
  - **Customer Phone Number** (10-digit numeric, optional)
- **Keyboard Navigation:**
  - Enter in Name field $\rightarrow$ advances to Phone Number field.
  - Enter in Phone Number field $\rightarrow$ saves customer details and advances focus directly to the unified Item Code box.
  - Escape $\rightarrow$ skips/closes and focuses the Item Code box.
- **Data Persistence:**
  - Customer Name & Phone are saved in active order draft state.
  - Attached to KOT slips (`kotSlip.customerName`, `kotSlip.customerPhone`).
  - Stored in Supabase `bills`, `tables`, and `kots`.

### 2.3 Multi-Order Tabs via <kbd>F1</kbd> Hotkey (`OrderWorkspace.jsx`)
- **Requirement:** Cashier taking an order on Table 3 can press <kbd>F1</kbd> when a new customer arrives to open another order draft (Tab 2, Tab 3, etc.) without losing any staged items or data on Table 3.
- **Workflow:**
  - Multi-order state array in workspace (`orderDrafts: [{ id, tableId, customer, items, ... }]`).
  - Pressing <kbd>F1</kbd> creates a new clean order draft (or cycles between active open drafts).
  - A retro Windows tab bar displays open tabs: `[Order 1: T3 - Rahul]` `[Order 2: T7 - Moosa]` `[+ F1 New Draft]`.
  - Pressing <kbd>F1</kbd> or clicking tabs switches active context seamlessly.
  - When an order fires its KOT or is cleared, that tab closes and switches to remaining open drafts.

### 2.4 Double <kbd>Enter</kbd> to Fire KOT / Print Bill (`OrderWorkspace.jsx`)
- **Current Problem:** In New Order mode on an empty item code field, pressing Enter once accidentally fires the KOT.
- **Solution:** Require a deliberate **Double Enter** (<kbd>Enter</kbd> $\rightarrow$ <kbd>Enter</kbd>) to fire the KOT or open Cash Memo bill print.
  - First Enter on empty code: displays a clear prompt badge `[Press Enter again to Fire KOT]` with a 2-second timeout window.
  - Second Enter within window: fires the KOT.
  - If the user types a code or presses another key, the confirmation resets.

### 2.5 Cash Memo: Preview Items Before PAX Prompt (`OrderWorkspace.jsx`)
- **Current Problem:** Entering Table 1 in Cash Memo mode immediately popped up the Number of Persons (PAX) dialog without letting the cashier see what Table 1 ate.
- **Solution:**
  - Entering Table 1 in Cash Memo loads Table 1's items and amount into the grid for clear inspection.
  - The cashier reviews the items and total.
  - Pressing <kbd>Enter</kbd> on the reviewed table THEN opens the Number of Persons (PAX) dialog.
  - Pressing <kbd>Enter</kbd> in PAX dialog prints the Cash Memo and moves the bill to Unsettled Bills.

### 2.6 F12 Settlement & Details of Bill Screen (`DetailsOfBillModal.jsx`, `SettlementModal.jsx`, `PosContext.jsx`)
- **Requirement:** In Details of Bill (or F12 settlement), selecting a bill displays its itemized dishes, rates, quantities, and amount.
- **Fix:** Decouple settlement data from physical table occupancy:
  - `openSettleModal(tableId, billNo)` loads items directly from the bill snapshot (`unsettledBills` / Supabase `items_json`), so clicking any unsettled bill displays its exact items and amount regardless of whether the table is empty or re-occupied.
  - `SettlementModal` binds directly to the bill's data and supports keyboard hotkeys: `1` (Cash), `2` (UPI), `3` (Card), <kbd>Enter</kbd> to settle, <kbd>Esc</kbd> to close.

### 2.7 Cancel Items vs Cancel Table (`-` Hotkey) (`CancelItemsModal.jsx`, `OrderWorkspace.jsx`, `PosContext.jsx`)
- **Current Problem:** Pressing `-` directly triggered table cancellation or subtable toggle without allowing selective dish cancellation.
- **Solution:** Dedicated **Cancel Items / Table Modal**:
  - Displays all ordered items on the active table with check/selection, quantity to cancel, and cancel reason dropdown.
  - Operator can select individual dish(es) to cancel, reducing quantity and generating a Cancellation KOT.
  - Dedicated option/button to "Cancel Entire Table / KOT" with reason and manager PIN authorization.
  - Updates Supabase `cancellations_audit` and `order_items`.

### 2.8 POS Outer Background Color to White (`#ffffff`)
- **Requirement:** Change outer background behind/below POS windows from light grayish blue (`#6c8fa8` / `--win-desktop`) to clean white (`#ffffff`).
- **Files:** `src/components/OrderWorkspace.jsx`, `src/components/DetailsOfBillModal.jsx`, `src/index.css`.

### 2.9 Section Names and Two-Tier Pricing: "General" vs "Family AC"
- **Rename Section:** Change `'AC'` (Tables 1 to 20) to `'GENERAL'`.
- **Maintain Sections:** `'FAMILY AC'` (Tables 21 to 40), `'PARCEL'` (0, 0B, 0C...), `'HOME DELIVERY'` (00 - MOOSA...).
- **Rate Logic:**
  - `GENERAL` section: uses `hallRate` (normal hall pricing).
  - `FAMILY AC` section: uses `acRate` (AC pricing).
  - `PARCEL` & `HOME DELIVERY` sections: use `acRate` (same as Family AC).
- **UI Updates:** Running Tables headers updated from `AC` to `GENERAL`.

### 2.10 Re-ordering Independence on Unsettled Tables
- **Requirement:** When Table 1's Cash Memo is printed, it moves to Unsettled Bills (e.g. `1(33, 1450)`).
- Table 1 becomes `AVAILABLE`.
- New guests can sit at Table 1 immediately; entering Table 1 creates a new clean order with its own new items and new bill number.
- System must never block or redirect to the unsettled bill when Table 1 is entered.

### 2.11 Supabase Migration 02 (`supabase/migrations/02_features_update.sql`)
- Do NOT alter `01_init_inamdar_pos_schema.sql`.
- Create `02_features_update.sql`:
  ```sql
  -- Add customer details
  ALTER TABLE tables ADD COLUMN IF NOT EXISTS customer_name TEXT DEFAULT '';
  ALTER TABLE tables ADD COLUMN IF NOT EXISTS customer_phone TEXT DEFAULT '';
  ALTER TABLE kots ADD COLUMN IF NOT EXISTS customer_name TEXT DEFAULT '';
  ALTER TABLE kots ADD COLUMN IF NOT EXISTS customer_phone TEXT DEFAULT '';
  ALTER TABLE bills ADD COLUMN IF NOT EXISTS customer_name TEXT DEFAULT '';
  ALTER TABLE bills ADD COLUMN IF NOT EXISTS customer_phone TEXT DEFAULT '';

  -- Update section constraint for tables
  ALTER TABLE tables DROP CONSTRAINT IF EXISTS tables_section_check;
  ALTER TABLE tables ADD CONSTRAINT tables_section_check 
    CHECK (section IN ('GENERAL', 'FAMILY AC', 'PARCEL', 'HOME DELIVERY', 'AC'));
  UPDATE tables SET section = 'GENERAL' WHERE section = 'AC';
  ```

### 2.12 Supabase Live Data as Single Source of Truth
- Remove hardcoded fallbacks and ensure `fetchLiveMenuItems()` loads dishes from Supabase `menu_items`.
- Realtime delta sync updates local in-memory structures instantly.
- Tables, bills, counters, transactions all hydrate from Supabase.
